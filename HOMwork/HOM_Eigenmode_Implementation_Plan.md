# HOM 本征模自动计算与结果导出实施计划

记录日期：2026-06-19

状态：第一阶段——专用 CST 本征模模板准备与能力审查

## 当前决定

暂不修改源码，也不启动自动化模块开发。

第一阶段由用户建立专用 CST 本征模模板。模板完成后，先根据 CST
实际能力讨论可计算项目、替代方法和允许留空的结果，再冻结自动化接口。

原始 `eigenmode_frequency_targets.csv` 只作为测量目标输入，禁止覆盖。

## 第一阶段：专用 CST 模板

模板应尽可能包含：

- 实际腔体、约 50 mm 半径束管和约 250 mm 半径腔体。
- FPC、pickup、HOM 波导或阻尼结构。
- 金属、铁氧体、陶瓷和其他已知材料。
- 明确的束流轴和区域命名。
- 本征模搜索频段及模式数量设置。
- 束管开放边界、PML 或 waveguide port。
- 可供自动读取的结果树和场监视器。

不要求模板第一次就支持全部目标字段。不得为了满足输出表而伪造 CST
不具备或未经验证的能力。

每项需确定：

- CST 2026 实际结果树路径。
- 使用的官方 API 或模板内预设导出方式。
- 物理定义、单位和归一化。
- 自动化程度。
- 失败时是留空、人工补录，还是采用替代计算。
- 是否适用于开放或传播模式。

## 重点讨论与妥协项

模板完成后优先讨论：

1. CST 是否支持当前边界条件下的开放本征模或复频率求解。
2. 2.30 GHz 以上传播背景能否形成可信离散模。
3. waveguide port 与本征模求解器是否能够同时满足。
4. 端口辐射功率及 `Q_external` 能否直接提取。
5. 有损材料与金属壁损耗能否在同一次求解中分解。
6. 横向 R/Q 的 CST 定义、单位和参考偏移。
7. 每个模式的复数三维场能否稳定批量导出。
8. 模态数量未知时，如何证明窗口内模式已经搜索完整。
9. 简并模式在网格变化后的跟踪方式。
10. 哪些传播目标应改用 driven-mode 或 wakefield 分析。

允许的妥协原则：

- 无可靠开放本征模时，不用封闭束管 Q 冒充真实传播模 Q。
- 无可靠损耗分解时，保留总 Q 和已有分项，其余字段为空并记录原因。
- 横向 R/Q 定义不清时不进行单位换算。
- 不能自动导出的场图允许使用模板内预设视图批量生成。
- 无可信离散模式时输出 `propagating_no_discrete_mode`，不强行匹配。
- driven-mode/wakefield 是否作为补充求解链，在能力审查后另行决定。

## 后续自动化边界

能力矩阵确认后，再冻结：

- CST 模板输入接口。
- 可自动计算的结果字段。
- 需要人工准备或复核的字段。
- 允许为空的字段及原因码。
- 模式匹配和置信度规则。
- 输出 CSV、manifest 和 `fields/` 的最终结构。
- No-CST 与 live-CST 验收范围。

在上述内容确认前，不开始实现本征模 workflow。
