## 1. 项目要解决什么

长期目标是把论文、专家知识、STEP/CST 工程转成可复用的 RF 工程知识，用于理解腔体、构造和修改几何、组织仿真及减少昂贵求解。语义图是实现这个目标的一种工具，其划分方式和必要粒度仍可修改。

当前 RF-CEM 重点是常温、轴对称、单 cell 的 RF 真空壁轮廓。希望新实例的引入逐渐减少手工编码和审核，而不只是把既有规则执行得更严格。

已有处理链：

```text
论文 / 人工审核 / 既有几何
  → literature_semantics + Helper2 + family_profile
  → R1 已标注实例图
  → R2 表示与编译 → 轮廓 / STEP
  → R4 几何观测与约束示例
              ↘ Workbench 展示

多个已标注实例图 → R3 结构差异与可选 motif 提案 → 审核 → grammar
原始资料 → 自动语义获取：目前只有 A0 几何信号覆盖探针
```

旧 500 MHz 几何→CST→标量结果→SAO 链另有历史实测基础，不能据此宣布新语义链已经具有完整 RF 物理闭环。

## 4. 2026-09-05 核查改变了什么理解

### A0 的参考边界包含编译器约定

`src/rf_cem/semantic/adapters.py::_build_sls2_graph` 将同一原生椭圆弧引用给相邻的两个语义区域。`src/rf_cem/compiler/adapters.py::_region_bindings` 按 owner 数量等分原始曲线的参数区间：

```python
start_fraction = index / part_count
end_fraction = (index + 1) / part_count
```

实际 v2 record 中，SLS-2 四段椭圆弧分别被分成 `[0, 0.5]` 和 `[0.5, 1]`。这些是**曲线参数比例**，不是全轮廓归一化弧长。A0 漏掉的 `junction.01/.03/.04/.06` 正好是这四处切分。

因此，A0 数值可以保留，但应解释为**该信号集对当前编译分区的覆盖率**。审核来源、坐标记录和 hash 一致，不足以证明这些精确分界坐标有独立的论文/专家标注依据。当前构造链没有为这些切点读取独立的定位证据；不能把它们直接用作“文献真值”。

本地 A0 记录：轮廓弧长约 **962.9486 mm**，`u=s/L`；覆盖容差 `Δu≤0.02` 相当于约 **19.259 mm** 弧长距离。命中点实际偏差约 **1.05–1.47 mm**，漏检点约 **43.07–65.86 mm**。容差和实测精度应分开报告。`Δu=0.01` 网格在该轮廓上约为 **9.63 mm** 弧长一个 atom。

这个结果否定了“当前信号集覆盖当前所有分区”的假设；没有证明所有几何方法都不能定位这些边界，更没有证明文献锚点是唯一可能来源。A0.5 oracle 若沿用这些标签，首先检验的是当前分区约定的可表达性。

### R3 的“学习”是有限结构归纳

`semantic/induction/engine.py` 按已有 region type 汇总残差，再使用 paired optional、single optional 和 alternative fallback 检测器。TD3 从 seed grammar 删除 nose 的允许规则，但输入图中的 `NoseRegion` 标签和既有 ontology 仍在。

它实际展示了：**给定已标注 nose 的实例，可提出把 nose 作为可选结构加入 grammar。**这是可复用的工程能力；尚不能称为从原始形状发现 nose 概念或开放语义学习。v1 support 是启发式支持度，不是概率。

`semantic/induction/blind.py` 用写在适配器中的 11 区序列构造 LEReC 图，并绑定论文证据；没有运行从论文自动提取该图的模型。LEReC 在原 R3 归纳输入中被留出，证明的是另一实例的已标注拓扑被接受。当前 A0 所查本地输入没有 LEReC 可重采样几何或带坐标 junction，不能直接做其边界定位测试；也不能因曾经留出而永远视作新的独立测试集。

### 先验和校验器不能代替识别能力

当前 R1 词表是固定六类；图还要求端点 BeamPipe、单一中心 Equator、nose motif，以及每个 side/type 的唯一语义键。这适合作为当前单 cell 模型，重复结构、新类型或不同定义可能需要调整。

给模型提供已知词表和领域定义可以是合理先验；真正要分开的是测试实例的答案、人工适配规则与模型可见输入。是否提示 grammar 应作为实验条件比较，而非预先规定一种写法才算“解耦”。

`unknown`、不一致检测和 grammar 校验能暴露部分问题；稳定地给出合法错误标签仍可能通过。新增先例是否改善下一实例，也需要测量，不能把“库变大”直接等同于“学会了”。

## 5. 阶段性研究方向与文字经验提案

本节记录讨论形成的研究目标与方法取舍，用于后续复盘；以下区分已确认方向、数据架构方案、用户已认可的基础经验及首轮对照结果。已执行经验提示实验，尚未实现新的学习模块。它替换此前把本层学习效果绑定到下游几何操作的建议。

### 已确认的核心问题与分层

**人指出具体划分错误，系统从 observe 中可观察的条件归纳可复用、可修订的经验，改善以后同类及新实例的判断。**“学习”必须改变以后的判断依据，不能以例库增大或固定词表补丁本身代替跨实例改善。

```text
划分：S = F(E, K)
学习：(E, S, 人工审计) → K_new
E：observe 提供的证据；K：已有经验；S：本次划分
```

划分使用已有经验；学习根据证据、本次结果和人的反馈修改经验。区分这两个过程，记录经验如何影响结果；整个学习循环与下游优化器保持独立。
本层主要评价对象是语义划分及其人工修正负担，不引入 RF 指标、优化器目标或下游几何操作效果作为主评价。
保留 `semantic / representation / compiler / observation` 的 OOP 分层；表示、编译及底层计算继续独立。
当前方向不要求微调商业 LLM；能够积累和使用外部经验，不等于商业模型权重已被训练。

### 学习什么，以及未知如何进入

- **已知结构：**改善判断条件、数值阈值、适用范围和例外，减少同类错误；已知概念的稳定判定与未知发现同样重要。
- **未知结构：**可以提出新类型，也可以形成子规则、已有概念的组合或拆分；不把每个异常都强制变成一个新类。
- **初始先验：**允许提供基础定义、几何操作与少量判例，不强求从零；后续知识不能全部由人工预写。

例如“赤道冠附近的切向角范围”可作为候选可计算规律，其条件和范围可以从判例改善；目前不把某个角度值或区域名称写成普适工程事实。
新名称不是学到新概念的充分证据；需要观察它是否形成可复用的区分，并在新实例中改变判断。
如果当前证据无法表达必要区别，应保留未知或待补证据，而不是靠更多规则文字制造确定性。

### 人工审计与经验的含义

反馈入口可以支持通过/不通过、1–5 分、A/B 比较、局部修正和自然语言说明；不要求人每次都提供完整正确分区。
整体评分适合筛选，具体错区和修正原因能提供更直接的学习依据；不同方法对反馈粒度的需要不同。
自然语言反馈应对应本例的可观察证据与具体区域/边界区间，避免只留下无法定位的泛泛评价。

| 记录含义 | 应如何使用 |
| --- | --- |
| 本例修正 | 本实例认可的修改；不能自动推广到整个腔型 |
| 规则猜想 | 从案例归纳的候选条件，允许被后续正反例修订 |
| 工作定义 | 为消除划分歧义采用的明确约定；注明适用范围，不冒充物理定律 |
| unknown | 证据或知识不足以作出当前判断，保留待处理位置 |

这些区别用于解释经验，不是新增逐项审批流程。人应集中指出有意义的错误，避免同一事实、规则和使用动作被反复确认。

### 五种方法的借鉴位置

| 方法与一手来源 | 可借鉴的机制 | 原研究边界 |
| --- | --- | --- |
| [ExpeL](https://arxiv.org/abs/2308.10144) | 以成功/失败经历提炼和修订自然语言经验，并检索成功案例辅助新任务；作为当前经验学习主线的参考 | 原任务经验并非 RF 工程判例；文本入库不自动保证经验有效 |
| [LILO](https://arxiv.org/html/2310.19791v2) | 从成功解法抽取公共程序/规则，形成可复用工具 | 原方法包括解题搜索、Stitch 压缩与自动说明，不只是 LLM 总结；压缩有用不等于语义正确 |
| [POPPI](https://arxiv.org/abs/2104.14426) | 利用正反例排除错误规律，并发明可复用的中间谓词 | 中间谓词不必是新类别，也不自带工程含义；原论文不是完整终身学习系统 |
| [GCD](https://arxiv.org/abs/2201.02609) | 在已知类别与未知样本混合时寻找新的分组，提示已有知识的缺口 | 未知簇不会自动获得工程名称；原方法训练视觉编码器，不能当作现成 LLM 记忆功能 |
| [FunSearch](https://www.nature.com/articles/s41586-023-06924-6) | 搜索判定表达或程序，依据本层判例表现比较候选 | 评价函数由人先定义；原方法依赖有区分度的反馈，不自动提供跨领域知识迁移 |

五种方法按实际瓶颈取长，不要求同时装入框架，也不把它们统称为强化学习。
ExpeL 的经验路线、LILO 的抽象、POPPI 的反例推理、GCD 的发现和 FunSearch 的搜索均是借鉴方向，不是已决定的软件依赖。

### 怎样判断改善，而不是只判断重复

同一规则被反复使用，只说明它容易被调用；独立的新审计正例和反例才为其有效范围提供证据。
重复划分不稳定可能来自知识不足，也可能来自证据歧义、输入变化或模型采样；稳定输出也可能稳定地犯错。
关注新实例的划分接受程度、需要修改的区域及人工修正负担，并记录相对已有经验是否改善。
不强求所有边界都有唯一精确坐标；在可接受范围内允许边界区间或明确工作约定。
区分本例记忆与新实例改善，不以例库规模、规则数量、重复一致率或 schema 通过率代替学习效果。

### 已确认的实现取向（2026-09-07）

先采用轻量自然语言经验。商业 LLM 负责提出划分、理解意见和归纳经验；代码负责观测计算、格式检查、调用与记录；数据库保存经验和案例。可以由同一模型在不同调用中承担划分与学习职责；多 agent 调度、插件和工作流暂不展开。
“自更新 prompt”是这一阶段的可用直觉：持久化经验 K 独立保存，每次由程序装入任务上下文。经验更新不等于模型权重更新，也不修改观测坐标约定或程序接口。
用户已认可第一批基础经验的标准化文字及经验组 run2 的划分思路；2026-09-11 同意进入框架搭建，当前先提交实施计划，首版优先论文截面图输入。经验库及学习服务尚未编码。此前对话示例和本地先验草稿不自动导入为认可的知识。

### 文字经验 MVP 数据与架构方案（2026-09-11 更新，尚未实现）

**范围与闭环。** 首版从论文截面图提取一条轴对称腔体的有序二维真空壁面轮廓，再实现连续、互不重叠的 region 划分；不要求镜像对称、固定区域数或固定类型。输入是 region-free 的观测证据 E 与文字经验 K，输出划分草稿 S。已有可计算曲线用于核对数值及提取效果，不作为新图像的预填答案；RF 优化与 CST 不参与本次学习闭环。

```text
论文截面图 → 选取轮廓、定标、拟合 → 代码观测 E ─┐
当前经验版本 K ────┴→ LLM 划分 → 草稿 S → 人工意见 H
                         E、S、H、K → LLM 归纳 → 新增/修订/停用经验 → K_new
新实例再使用 K_new；下游曲线表示与编译单独衔接
```

**经验本体。** 一条经验保存一个可以独立修订的判断，必要条件和例外用文字表达。字段名是拟议接口；用户只需提供自然语言，程序与模型辅助整理其余内容。

| 字段 | 内容与约定 |
| --- | --- |
| `id`, `revision` | 自动生成的稳定编号与版本；修改保留旧版本，历史尝试引用当时版本 |
| `text` | 观察到什么、建议怎样划分，以及必要的理由和例外；先不转换成 DSL 或可执行代码 |
| `scope` | 适用对象、条件及已知限制的文字说明；未明确时写“尚未界定”，不默认普遍有效；首版不当作硬编码筛选器 |
| `kind` | `hypothesis` 表示可修订经验，`convention` 表示用户明确采用的工作定义；人提供的猜想仍是前者，不按作者身份推断真伪 |
| `origin` | 本版本由谁提出、来自用户原话还是哪些审计记录；基础经验直接保留原话，归纳经验通过审计引用回到案例与观测 |
| `enabled` | 当前是否加入划分上下文；停用保留历史。这不是正确率或审批状态 |

`text / scope / origin` 对应判断、适用范围、依据关联三个核心内容。不先增加置信度公式、使用次数权重、规则优先级或单独的反例数据库；反例可通过审计引用定位，并体现在经验文字或范围的修订中。模型自称引用某经验不证明实际因果贡献。

**一次固定的观测输入。** `ObservationSnapshot` 是案例输入，不是一条经验：包含 `id / case_id / contour_id`、原始几何来源与有序段映射、坐标原点和方向、总弧长、采样及计算参数、数值证据。论文输入另保存 PDF 页/图/裁剪位置、选中的矢量路径或有序像素点、像素/PDF 坐标到物理坐标的标定、尺寸来源及轮廓修正记录。几何修改后产生新 snapshot，不让旧引用随输入文件覆盖而改变；轮廓修正与语义反馈分别记录。
全轮廓位置统一为 `u=s/L ∈ [0,1]`，同时保留 `z_mm / r_mm`；`L` 为当前轮廓计算弧长，标明数值近似方法。切向角规定相对 `+z` 轴沿 `+r` 方向增加，单位 deg；曲率记录符号约定与 `1/mm`。不得把全局 `u`、单 region 归一化位置或原生圆弧/椭圆参数混用。
首版证据包含轮廓采样、切向、曲率及现有极值/连续性候选；给模型的紧凑视图保留关键变化与采样分辨率，必要时由代码补查局部区间。候选点仅提示位置，不强制成为切点；`z=0` 穿越也不等于已经证实几何对称。原始 PDF 引用与重建曲线引用分开保存，不把后者细节自动视为前者的标注。

**围绕经验的另外三类记录。** 与 `Experience` 合计四类主记录；观测 snapshot 单独作为输入文件保存。

| 记录 | 最小内容 | 目的 |
| --- | --- | --- |
| `PartitionAttempt` | `id / case_id / observation_ref`、本次提供的经验 `id + revision`、`partition`、实际请求与返回记录 | 固定本次的 E、提供给模型的 K 和产出的 S；请求同时记录模板版本、模型及实际调用参数 |
| `Review` | `id / attempt_id / targets`、人工原文；可选通过/拒绝、1–5 分、修正、另一尝试的比较引用 | 允许只审计整体、某个 region、某个切点或局部弧长区间；缺少局部意见不表示认可 |
| `ExperienceChange` | `id / review_refs`、模型对意见的解释、操作列表、新旧经验版本引用及修改理由 | 说明从哪些反馈得到了哪些改变；仅有整体拒绝而不能归因时，允许操作为空 |

人工明确提交的本例修正属于 `Review`；模型从自然语言推测出的修正属于 `ExperienceChange` 的解释，不能混写成人工原话或已确认答案。整体拒绝只否定本次整体方案，不制造逐 region 负例；通过也不把所有随 prompt 提供的经验都计为新的独立支持。

**划分草稿的形状。** `partition` 由有序 `boundaries` 和相邻边界之间的 `regions` 组成。每个切点有局部 `id / u`，可附 `u_range=[lo,hi]` 表达位置不确定性；这不是 region 的覆盖区间，也不是概率置信区间。相邻 region 引用同一个切点，避免各自报出互相矛盾的接缝位置。
每个 region 保存局部 `id / start_boundary_id / end_boundary_id / label`，附简短判断说明、观测引用及模型声称依据的经验引用。`anchors` 单独保存 wall/equator/nose 等定位点的 `id / u / label / evidence_refs`，可引用现有切点，也可位于区段内部；点不自动变成零宽 region 或新的切分。`label` 是开放字符串，`null` 明确表示未知；新名称是候选判断，不自动成为已确认工程类型。同名 region 可以出现多次。
代码只检查数值有限、切点有序且覆盖 `[0,1]`、区间与引用有效等数据条件；不以旧 R1 的六类词表、成对 nose 或唯一 equator 校验新草稿。几何覆盖与语义接受分别记录；未知 region 仍占据具体位置。

**调用与更新。** `partition(E,K)` 和 `learn(E,S,H,K)` 是两个职责明确的方法，由同一个可替换模型接口提供能力。初期把全部启用经验按稳定顺序装入上下文，暂不引入向量检索；若超过输入预算，明确报告或调整上下文，不能静默丢弃经验。案例按需提供，并记录实际提供了哪些审计内容。
人工审阅提交后，学习调用读取对应观测、草稿、原始意见及相关旧经验，输出 `ADD / REVISE / RETIRE` 数据操作。首版建议自动保存修订并展示一句修改摘要，允许撤销到旧版本；不要求同一意见再经过逐条规则审批。格式有效不代表经验成立，归纳经验以 `hypothesis` 身份继续接受新案例检验。
用户明确的工作定义保持其来源身份；模型可以指出冲突并提出替代猜想，不能擅自改写后仍称其为用户约定。经验冲突先在本次判断中列明涉及的条件，必要时保留未知，再由后续案例与反馈收窄范围；不按“更新更晚”或“用得更多”决定真伪。

**代码与存储落点。** `observation/` 增加不依赖已知 region 的几何观测入口，接收有序曲线并生成 E；可计算曲线及导数适配属于无语义的 `representation/`。`semantic_acquisition/` 组织本轮应用：`image_input.py` 负责图像/矢量提取与定标适配，`contracts.py` 放草稿及经验记录，`store.py` 保存记录，`service.py` 组织上下文与两个模型职责，扩展既有 CLI；页面只负责叠图与收集修正。图像/观测代码不读经验库，也不按 region 标签改变拟合。模型通过窄接口注入，不建设 agent 管理平台。
持久化建议一个本地 SQLite，保存经验版本、尝试、审计、经验修改四类记录；可变内容先用 JSON payload，基础编号与引用用普通列，经验更新在一次事务中写入。观测快照及必要的较大请求/图像文件按编号保存于同一运行目录。采用现有 Python 数据类、标准库 SQLite/JSON，不引入数据库服务或新的 schema 框架；运行数据不提交 Git。Workbench 如需展示，只读取这些记录并生成视图，不拥有知识本体。

**复用与现有接口限制。** `semantic_acquisition/boundary_signals.py` 已有无标签 `BoundaryTrace`、弧长采样、曲率和候选点；复用其有序轮廓与事件思路，修正跨接缝差分及近零区间压成一点的问题。历史 `CompileRecord → BoundaryTrace` 保留为对照输入，新的论文入口直接接无标签轮廓，避免先经 R1 标注。当前 R4 observer 依赖已知 region，不能原样充当前置 observe。现有 `representation` 端点曲率是非负幅值，新接口另外计算有向曲率，不改变旧接口含义。
现有 R1 构造器限制固定六类、终态审计、唯一 `side:type`、中心 Equator 与两端 BeamPipe；新草稿不强行塞入它。后续再做草稿到表示/编译的明确适配；不兼容的新类型保留原义。旧 `_region_bindings` 按 owner 数等分原生参数，不是学习边界的转换器；真正衔接时要计算全局弧长位置到源曲线参数的映射。该适配不阻塞文字经验闭环。

**首轮怎样检验。** 软件实现首先完成：导入用户经验 → 对一个轮廓划分并展示 → 保存局部或整体意见 → 产生可见的经验修订 → 对另一实例再次划分。通常每个受审实例是一轮划分调用和一轮学习调用，额外查询与重复采样按实际需要增加；先记录实际调用费用与人工审阅耗时。
学习效果用学习前后的经验分别处理同一新实例，保持观测一致并由人比较；后续补查已有审计案例是否出现退步。已用于归纳的案例修好只能说明本例修正，不能代替迁移证据；测试审计意见只在结果产生后进入学习。一次改善是可行性信号，后续按差异和不稳定情况补样本，不预设大规模基准或百分百可靠承诺。
实现时验证关键数据往返、历史版本引用、局部审计定位与未知标签保留，再按仓库要求运行涉及持久化/schema 的分支 no-CST 检查。具体采样预算、提示词措辞和后续检索策略在首批真实案例中调整；本次仅提交方案供审阅。

### 论文轮廓与 evidence 的首版实施顺序（2026-09-11 计划）

**首例选择。** 优先现有 SLS-2 论文 Figure 6 的 CAVITY #1：其轮廓与此前案例对应，可结合正文的 `L=680 mm / r=50 mm` 分别标定轴向、径向，再以表中其余尺寸和已有重建曲线作一致性核对。Figure 1/3 是参数化示意，不能直接当作同一个数值实例。已查看本地第 4/6/8/9/11 页：第 4 页存在矢量曲线路径，Figure 6 所在第 11 页有嵌入图像；尚未实现自动选路或轮廓提取。来源为既有 `papers/sls2/source.pdf`，不需要重新抓取资料。

| 顺序 | 交付 | 首版做法 |
| --- | --- | --- |
| 1. 图到轮廓 | 原图与提取轮廓叠图、坐标标定、有序曲线文件 | 用户/LLM 选图、选真空边界、识别尺寸出处；程序优先读取 PDF 矢量路径，栅格图采用区域选择、边缘/颜色提取与少量人工纠正。先提取 Figure 6，再用已有含矢量示意图检查另一种输入 |
| 2. 轮廓到证据 | 一份 E JSON、轮廓/切向/曲率图、可补查局部区间 | 按几何连续顺序参数化，不按 z 排序；从同一曲线计算坐标、导数、弧长及事件。图和文字摘要均由 E 生成 |
| 3. 一次划分与审阅 | 六条经验输入、开放草稿、叠图、局部自然语言反馈 | 两个模型方法 `partition / learn` 共用一个可替换传输接口；先生成固定 UTF-8 请求包、通过现有独立模型调用并导入结果，自动 API 传输随后替换。请求文件生成不算已完成模型调用 |
| 4. 经验更新与新例使用 | 经验版本差异、一次新划分、原有案例回看 | 保存原话，模型归纳新增/修订/停用，显示修改摘要并可撤销；全部启用经验顺序装入。wall 定位与范围、nose/blend 分隔为首批学习对象；新例结果由用户比较 |

图像提取中的人工操作用于确认“哪条可见线代表壁面、怎样定标、哪里被标注遮挡”，不要求先标 nose/wall 等语义。尺寸 OCR 可以由 LLM 提议，标定数值与出处由程序保存；图中只有半腔或被裁切时明确范围，不自动镜像补全。遮挡段的插补另作记录，缺少证据时可保留局部未确定轮廓，不让语义模型把补线当作直接观察。

**证据质量先解决四件具体事。**

1. **图形来源与尺度。** PDF 矢量优先保留绘图曲线，但绘图路径也不是原 CAD。分别处理轴向与径向缩放；缺绝对尺寸但比例可信时可使用归一化形状，不伪造 mm。比例不明时不声称图上角度是物理角度。首例使用有尺寸的图，避免一开始扩展完整缺尺寸推断系统。
2. **轮廓位置与曲率分开检查。** 原图叠线让人快速看到是否走错线；像素偏差、线宽或拟合残差描述轮廓位置，不能充当曲率误差界。栅格点用沿轮廓参数的平滑拟合，不强制 `r=f(z)`，保留鼻锥回折；先做一般光滑曲线，不因已有 region 经验而强行拟合成圆弧/椭圆。
3. **有向导数与接缝。** 拟合后由代码求切向与有向曲率；原始点、拟合方法与局部估计属性保留。尖角保留左右切向，直段保留区间，真实断口不画隐形连接桥。点云加密不会增加原图的信息；必要时改变一个合理的局部平滑尺度，标出随之消失/漂移的曲率变号，不把每个小波动都报成结构。
4. **证据可定位且不预判语义。** E 包含 `u=s/L`、已定标坐标、切向、曲率、半径极值/平台、曲率符号区间、轴向回折与接缝信息。每个局部证据说明对应原图位置、计算方法及是否插补/数值敏感；高/中语义倾向来自经验，不等于几何测量精度。紧凑摘要附轮廓图并保留全量数据；未知结构缺少区别特征时可以请求一个具体几何补测，再由代码实现和记录。

**最小验证及成本安排。** 用少量已知曲线的合成图检查像素定标、顺序及平滑误差，再检查真实论文图的叠线；两者分别回答数值算法是否正确、真实图是否提取合理。解析用例覆盖正反向曲率、带直段的变号、接缝及回折。真实图上的人工审阅接受程度与后续语义改善另计。首版成本主要在图到轮廓和局部纠正交互，其次是数值处理；经验 CRUD 与两次模型调用较小。先用一个轻量叠图/编辑页面和文件交换完成闭环，后续再增加批量找图、自动标定、STEP 输入或大量经验检索。

可参考的现成能力：[PyMuPDF 矢量路径提取](https://pymupdf.readthedocs.io/en/latest/recipes-drawing-and-graphics.html#how-to-extract-drawings)、[WebPlotDigitizer 定标、手动与自动提取](https://automeris.io/docs/digitize/)。后者可作为初期提取/校正工具，通过有序坐标及标定记录导入；不能直接使用按 x 排序的提取方式处理回折。当前项目 `.venv` 尚无 PyMuPDF/OpenCV；本轮没有安装依赖，代码阶段只补选定路线必需的依赖。

### 第一批基础经验（2026-09-10，用户已认可文字）

以下编号已用于对照实验的文字输入，尚非经验数据库记录。共同 `scope` 为沿束流轴旋转对称的二维裸腔真空壁面母线，允许单腔、多腔和局部重入；共同 `kind=hypothesis`，来源为 `user_seed`。标准化表述由助手提出并获用户认可，原话与位置澄清保留在下方；首轮案例结果见下一小节，不代表通用有效性。“高度倾向／中度倾向”保留用户的判断强弱，不转换成概率或权重。

**统一观测含义。** 按母线的连续连接顺序从入口端遍历到出口端，局部可沿轴向回折，不能按 z 排序重排点。局部极值按腔室尺度识别，不只取全轮廓最大的一个点；“凸性变换”指二维母线带符号曲率由正变负或由负变正，“单凸性”指一段内保持同一弯曲方向、没有明确变号，曲率大小可以变化。曲率为零与曲率变号不同，拼接处也可能从一侧符号直接跳到另一侧。切向与束流轴平行包含同向和反向；切向垂直、曲率变号、半径极值是不同观测事件。

| 临时编号 / 主题 | 标准化经验正文及局部适用条件 | 原始来源 |
| --- | --- | --- |
| E01 赤道 | 在腔室尺度上，半径的主要局部极大点或高半径平台，高度倾向识别为 equator 锚点或候选区域；多腔分别考察各腔室的主要峰/平台。光滑内部极大点的切线与束流轴平行，但候选区域的每一点不必平行。 | 第 1 条 |
| E02 束管端部 | 在完整腔体的已知入口/出口侧，较小半径且与端部管状通道连续相接的区段，高度倾向识别为束管/端部口径区；存在近恒定半径管段时，可进一步称为 beam_pipe。低半径与平行切向需结合端部位置、邻接关系判断，不要求束管半径等于全腔最小值。 | 第 2 条；助手补充端部与邻接条件 |
| E03 腔间 iris | 位于相邻两个腔室膨大区之间的主要局部缩颈或低半径平台，高度倾向识别为 iris 锚点或候选区域。光滑内部极小点的切线与束流轴平行；不把任意小凹陷都视为一个新腔间 iris。 | 第 2 条 |
| E04 腔体侧壁 | 在 iris/束管侧与赤道之间，主要曲率变号位置，或连接两侧相反弯曲趋势的近直线段，高度倾向作为 cell_wall 的定位依据；切向接近垂直也是线索，但不是必要条件。允许倾斜壁面、无垂直直段或只有 wall 锚点的光滑过渡。 | 第 3 条；近直线连接为助手显式化补充 |
| E05 平滑过渡 | 已识别的功能区域之间，若连接区段平滑且保持单一弯曲方向，高度倾向识别为 blend；主要用于 wall—equator，也按用户最终序列用于排除鼻锥等独立结构后的 iris/束管侧—wall 连接。单凸性说明可作简单过渡候选，并不要求圆弧或恒定曲率。 | 第 4 条前半与最终序列 |
| E06 鼻锥与复杂过渡 | 主要在束管或 iris 与 wall 之间，若出现额外曲率变号、局部轴向回折或向腔内伸出的独立凸起，中度倾向考虑鼻锥、重入过渡或其他附加结构；鼻锥命名还应结合近束流孔位置和向腔内伸出的整体形态。其他位置的异常先保留为附加结构候选，未知时不强行命名。 | 第 4 条后半与本轮位置澄清；几何条件经助手修正 |

`cell_wall`（腔体侧壁）是助手建议的项目名称，保留用户 `conductive wall` 的对应关系：金属腔体其他壁面同样导电，导电性本身不区分此 region。`nose` 是功能部位的候选名称；“局部回折/重入形态”先是几何特征，不能仅因具有该特征就创建 nose region。

**必须保留的数学修正。** 光滑、非退化轮廓内部的半径极值已蕴含平行切向，两者不能当成两份独立支持；轮廓截断端点不适用这一结论。切向角超过垂直方向不必新增一个曲率变号点：例如角度沿一段从 0° 增至 110° 再降至 0°，已经存在局部轴向回折，曲率只需变号一次。接回束管是否再变号取决于当时的转向，不能由“超过 90°”单独推出。程序以后可用沿入口到出口遍历时 `dz/ds<0` 表达局部轴向回折，避免不同角度约定的歧义。

**点与 region 的范围。** 这些经验首先提供锚点、候选区域和结构解释；单个极值或拐点尚未确定有限宽 region 的边界。赤道/iris 的外缘、wall 附近取多宽、与 blend 在哪里交接，留给后续经验与局部审计积累；真实直段或平台的范围可直接成为候选。没有有限宽 wall 证据时可保留定位锚点，不人为切出等宽小区域。初始数据契约应允许保留这种语义锚点，不能只接收已完成的有限区间划分。
用户的 `束管入口区 → (可能的鼻锥) → blend → conductive wall → blend → 赤道` 保留为常见半腔组合示意，不另记一条强制拓扑规则；多腔可用 iris 作为半腔的低半径端。几何不存在的独立区域无需补齐，同名过渡可以重复出现。

来源核对仅用于校准表述：[Fermilab 第三谐波腔论文](https://accelconf.web.cern.ch/p03/papers/TPAB014.pdf) 给出了 30 mm iris 与 40 mm 束管的实例，支持两者半径不能强制相同；[SRF2021 行波腔论文](https://accelconf.web.cern.ch/srf2021/papers/weocav04.pdf) 使用自身定义的 α<90° 描述重入，说明角度约定必须明确；[CERN RF 课程第 11 页](https://indico.cern.ch/event/1149120/contributions/4822292/attachments/2431875/4164566/doctoral_school_04_22_RF.pdf#page=11) 将 nose cone 表述为向腔内的凸出部位。上述来源没有验证这六条经验的通用识别准确率。
